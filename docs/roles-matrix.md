# Матрица ролей

Этот документ описывает ролевую модель **web API и Mini App**. Реализация определения пользователя находится в `app/web/dependencies.py`; маршруты и их проверки — в `app/web/routes.py`. Команды Telegram-бота имеют отдельные обработчики и не всегда совпадают с web-интерфейсом.

## Роли в web

| Роль | Как определяется | Основные возможности | Ограничения |
|---|---|---|---|
| Пользователь | Нет активной подписки и нет управляемого канала с действующей подпиской | Просмотр афиши, покупка/возврат билета, просмотр билетов и QR, профиль, привязка identity, добавление VK-группы | Не может создавать и управлять мероприятиями без статуса организатора |
| Организатор | Есть активная подписка пользователя или управляемого канала | Создание, публикация и управление своими мероприятиями; продажи, статистика, check-in; площадки, приглашения, промокоды, динамические цены и premium-функции события согласно тарифу | Не может управлять чужими мероприятиями/каналами |
| Организатор с площадкой | Организатор, у которого есть канал с действующей подпиской или подключённая VK-группа (`has_group`) | Возможности организатора плюс подключённая площадка для публикаций | Те же ограничения организатора |
| Супер-админ | Telegram ID указан в `ADMIN_TELEGRAM_IDS`; приоритетная роль `super_admin` | Глобальная статистика и здоровье; просмотр/поиск/мягкое удаление пользователей; выдача пользователю подписки; создание и просмотр Telegram-каналов, управление подпиской канала и её администратором; рассылка | Не получает организаторские права, не создаёт и не редактирует мероприятия организаторов, не управляет их VK-группами через self-service |

## Правила и детали

- Супер-админ определяется только для Telegram identity. Его роль имеет приоритет над обычной подпиской: `is_creator` для него остаётся false.
- Организатор определяется по активной подписке пользователя и/или действующему управляемому Telegram-каналу. VK-группа влияет на `has_group`, сама по себе подписку не заменяет.
- `has_group` — отображаемое состояние площадки; оно не является отдельным уровнем прав.
- TG- и VK-identities могут быть связаны с одним каноническим пользователем через `UserIdentity`.
- Пользователь может запросить подписку через `POST /me/subscription`, а организатор может купить premium для события через `POST /me/events/{event_id}/premium`. Сейчас эти маршруты активируют возможности без списания реальной оплаты.
- VK Pay — отдельный web-поток для покупки билетов. Он доступен, когда `VK_PAY_ENABLED` и credentials настроены.
- Супер-админские API: `/admin/users`, `/admin/channels`, `/admin/stats`, `/admin/broadcast`, `/admin/health`. Защищены `require_super_admin`.
- Организаторские API мероприятий защищены проверкой `is_creator` и проверками владения/доступа к каналу.

## Основные сценарии

1. Пользователь открывает Mini App, просматривает мероприятия, покупает билет и показывает код/QR на входе.
2. Пользователь активирует подписку и получает возможности организатора. В текущем API это тестовая активация без реального платежа.
3. Организатор добавляет Telegram-канал или VK-группу, создаёт мероприятие, публикует анонс и проверяет билеты.
4. Супер-админ выдаёт подписку пользователю или каналу, просматривает глобальные данные и выполняет административные операции.

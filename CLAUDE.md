# TicketBot: проектные правила и обзор

TicketBot — система продажи билетов с общим Python-ядром, платформенными ботами и FastAPI Mini App. Наличие реализации в репозитории не подтверждает её текущую доступность в production; статус развёртывания уточняйте отдельно.

## Источники по устройству проекта

- `README.md` — краткий обзор и локальный запуск.
- `docs/how-it-works.md` — архитектура, потоки данных и схема БД.
- `docs/roles-matrix.md` — роли web API/Mini App.
- `docs/user-flows.md` — пользовательские сценарии и их тестовое покрытие.
- `docs/user-manual.md` — инструкция пользователя.

При описании доступных команд Telegram сверяйтесь с `_register_handlers()` в `app/platforms/telegram/bot.py`: обработчик, объявленный в файле, не обязательно зарегистрирован. Сейчас Telegram-бот открывает Mini App, обрабатывает deep links покупки/приглашения и обновления участников каналов. VK- и MAX-адаптеры содержат базовые команды пользователя. Полноценное управление мероприятиями доступно через web API/Mini App.

## Терминология

| Термин | Значение |
|---|---|
| Супер-админ | Telegram ID из `ADMIN_TELEGRAM_IDS`. В web имеет глобальные административные возможности для пользователей и Telegram-каналов, статистики, рассылки и здоровья. Роль не даёт организаторские права на мероприятия. |
| Пользователь | Посетитель: просматривает мероприятия, покупает/возвращает билеты и предъявляет билет на входе. |
| Организатор | Пользователь с активной подпиской пользователя или управляемого Telegram-канала. Создаёт и управляет своими мероприятиями. |
| Организатор с площадкой | Организатор с Telegram-каналом с действующей подпиской и/или подключённой VK-группой. |
| Канал | Telegram-канал, подключённый для мероприятий и публикаций. Подпиской канала и его администратором могут управлять супер-админские функции. |

Подробные web-права — в `docs/roles-matrix.md`. Подписка пользователя и premium события в текущем API активируются без реального платежа; VK Pay — отдельная конфигурируемая интеграция покупки билета.

## Структура кода

```text
app/core/       модели, сервисы, схемы, БД и общая бизнес-логика
app/web/        FastAPI, REST-маршруты, Mini App авторизация и статика
app/platforms/  адаптеры Telegram, VK и MAX
app/bot/        точки запуска: telegram, vk, max, web, seed
migrations/     Alembic-миграции
tests/          pytest, API и сквозные сценарии
deploy/         Docker Compose и сценарии развёртывания
```

Точки запуска используют пакет `app`: `python -m app.bot.telegram`, `python -m app.bot.vk`, `python -m app.bot.max`, `python -m app.bot.web`. Docker Compose по умолчанию включает PostgreSQL, Web и Telegram; VK/MAX доступны в профиле `all`.

## Правила разработки

### Тесты

Изменения логики, моделей или API должны иметь соответствующие тесты. Используйте окружение, эквивалентное CI/deploy; dev-зависимости должны быть явно указаны в `[project.optional-dependencies].dev` в `pyproject.toml`. Для ручного запуска тестов нужен настроенный PostgreSQL.

### Документация и учёт

- Новые задачи и их статусы ведутся в `docs/tasks.md`.
- При исправлении подтверждённой ошибки анализ и результат фиксируются в `docs/errors.md` согласно принятому там формату.
- Изменение поведения или запуска сопровождается обновлением соответствующей документации.
- Перед началом работы сверьтесь с актуальными задачами и документами, но при противоречии проверяйте код.

### Ветвление

- Основная ветка — `main`; рабочая — `dev`.
- Каждое изменение ведётся в отдельной ветке от `dev`, с уникальным понятным именем (`bugfix/`, `feature/`).
- После завершения изменения отправляются в PR для `dev`; в `main` мержит автор проекта.

### Конфигурация и секреты

Секреты хранятся в локальных `.env.*` и GitHub Secrets, не коммитятся. Шаблоны находятся в `.env.*.example`. Схему БД в production обновляйте Alembic-миграциями; `init_db()` с `metadata.create_all` — вспомогательный bootstrap, не замена миграциям.

### Добавление платформы

1. Добавить адаптер в `app/platforms/<platform>/` и отдельную точку запуска в `app/bot/`.
2. Переиспользовать сервисы `app/core/`, не дублировать правила покупки/возврата.
3. Настроить зависимости, Compose/env и документацию платформы.
4. Добавить тесты поведения платформы и общих потоков, которые она поддерживает.
